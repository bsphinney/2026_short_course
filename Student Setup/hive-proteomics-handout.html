Running Proteomics Searches on Hive

Student handout 2 — use Claude Code on the cluster to search real mass-spec data.

Do handout 1 first. This picks up where Getting Started with Claude Code left off. You should already have Claude Code installed and the course API key working.

What you need from your instructor: your personal Hive login — a username like proteomics-class-07 and its password. Each of you gets your own; please don't share or swap them.

1 Log in to Hive

Open a terminal (macOS/Linux) or PowerShell (Windows) and connect, using your account number:

ssh proteomics-class-07@hive.hpc.ucdavis.edu

Type the password when prompted. Nothing appears as you type — that's normal, just press Enter. The first connection asks you to confirm the host fingerprint; type yes.

You'll land in your own home directory, /home/proteomics-class-07.

2 Start Claude Code on Hive

Go to the shared course folder your instructor points you at and run the launcher. The first run installs Claude Code into your home directory (about a minute, no admin needed):

bash start-claude-code.sh

Then run the same command again to actually start it. After the first install you can also just type claude from anywhere.

Hive has outbound internet, so Claude Code can reach the API from the cluster — this is already tested and working on the class accounts.

3 Install the proteomics pipeline skill

This is the part that turns Claude Code into a proteomics analyst. The skill knows the validated UC Davis Proteomics Core workflows — which search engine to use, the right mass tolerances for each instrument, and how to run everything correctly on the cluster.

Inside a Claude Code session, type these two commands:

/plugin marketplace add bsphinney/DE-LIMP
/plugin install ucdavis-proteomics-core-pipeline

You only do this once per machine. Confirm it's there with:

/plugin

On Claude Desktop instead?

Go to Customize → Plugins → Browse plugins, add the marketplace bsphinney/DE-LIMP, then install ucdavis-proteomics-core-pipeline the same way.

4 Find the course data

The class datasets live on the group share, which your account can already read:

/quobyte/proteomics-grp/2026_shortcourse_data/

Have a look around:

ls /quobyte/proteomics-grp/2026_shortcourse_data/raw_data/

Read-only, please. The group share holds other people's real data. Read from it, but always write your results into your own home directory. The examples below all do this.

5 Run your first search

Start Claude Code from your home directory and just ask in plain language. For example:

Search this timsTOF DIA file with DIA-NN and tell me how many
proteins were identified. Put all the results in my home directory.

/quobyte/proteomics-grp/hela_qcs/timstofHT/dia/06Aug2025_HeLa50ng_DIA_100spd_S1-A2_1_15663.d

The skill will work out that this is DIA data from a timsTOF, pick the matching validated workflow, pull the right human FASTA, write a cluster job script, submit it, and watch it until it finishes. It will ask you to confirm before it commits any real compute — read that summary before saying yes.

When you have several files and a real experimental design, the same skill takes you all the way to differentially expressed proteins. Tell it which samples are which:

The first three files are control and the last three are treated.
Run the full DIA analysis and give me the differential expression results.

6 The cluster rules — this part matters

Never run a search directly in your terminal on Hive. When you log in you're on a login node, which is shared by hundreds of people. Real searches must be submitted as jobs with sbatch, which sends them off to the compute nodes. Running a heavy job on the login node will get it killed and your account flagged. The skill handles this for you — but if you ever write your own script, submit it.

Your class accounts run under the Slurm account publicgrp, and there are two partitions you can use. The difference matters:

low — use this by defaulthigh
CPUs per jobNo limit8 maximum
Memory per jobNo limit128 GB maximum
Max wall time7 days30 days
CatchCan be interrupted and automatically restarted if a paying group needs the nodeNever interrupted, but the whole class shares a small pool

Use low. The 8-CPU ceiling on high makes searches slow, and that pool is shared with roughly a thousand other campus users. On low you can ask for 32 CPUs and your search finishes in minutes. Add --requeue so it restarts itself on the rare occasion it gets bumped.

If you write your own job script, the header should look like this:

#!/bin/bash -l
#SBATCH --job-name=my_search
#SBATCH --partition=low
#SBATCH --account=publicgrp
#SBATCH --cpus-per-task=32
#SBATCH --mem=64G
#SBATCH --time=08:00:00
#SBATCH --requeue
#SBATCH -o my_search.%j.out
#SBATCH -e my_search.%j.err

64 GB is generous — a single-file DIA-NN search of a human sample actually peaks around 11 GB. Don't request hundreds of gigabytes you won't use; it just makes you wait longer in the queue.

7 Watch your job

Submitting prints a job number. Use it to check on things:

# is it queued (PD) or running (R)?
squeue -u $USER

# what happened to a finished job?
sacct -j 19457532 --format=JobID,State,Elapsed,MaxRSS

# watch the output as it's written
tail -f my_search.19457532.out

Press Ctrl-C to stop watching (this does not kill the job). To actually cancel a job: scancel 19457532.

You can log out and your job keeps running — come back later and check on it.

8 What a good result looks like

Here's a real run on the class accounts, so you know what to expect. One HeLa 50 ng DIA file from the timsTOF HT, 100 samples-per-day gradient, searched library-free against the human proteome:

Run time6 minutes 23 seconds on 32 CPUs
Peak memory11 GB
Precursors identified35,952 at 1% FDR
Protein groups4,466 at 1% FDR

Your main results file is report.parquet. Alongside it you'll get report.pg_matrix.tsv (protein groups × samples — the table most people actually want), report.stats.tsv (a QC summary), and report.log.txt. Ask Claude Code to explain any of them.

Sanity check your own runs. If a short-gradient HeLa run gives you a few hundred proteins instead of a few thousand, something went wrong — wrong FASTA, wrong instrument settings, or a bad file. Ask Claude Code to look at report.log.txt and the QC stats with you. Getting a number is easy; knowing whether to believe it is the actual skill.
Two shared budgets, both easy to blow through.
  • The API key ($500 for the whole class). Stay on the default Sonnet model — check with /model. Have Claude Code read result files from disk rather than pasting big protein tables into the chat. /exit when you're done.
  • The cluster. Don't submit twenty jobs to see what sticks, and don't request hundreds of CPUs or gigabytes you won't use. One well-specified job beats ten speculative ones.
